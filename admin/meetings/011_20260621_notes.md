- Front-end should be our focus first. Some things that are going to be useful for us:

- For our initial design, we should focus on the simplest case first. That being our initial design only supporting multiple choice type questions (i.e. ignore drawing, ignore text input, etc).

### Starting Ideas
- Pages
  - Home / Login screen
    - Example: one button could be for student, another for instructor (basic case)
  - Student View
    - Your classes (think Canvas)
    - Once a user clicks on a class, example subpages could be:
      - Answering area (where they wait for the instructor to put up a question)
      - Your "gradebook" (basically, how many check-ins/questions have you participated in total?). It might be helpful to have a table that shows data on that (not necessarily required).
  - Instructor View
    - Your classes
    - For each class:
      - A list of categories/tabs they can create such that each category has X questions the professor wants to use for the day. For example, the intructor can have a tab called "Jun 21 Participation","Jun 30 Participation", etc. to help them organize. Each one could be opened and show their X questions.
    - For each question,
      - A page that lets the professor edit the question content. Perhaps this should function such that it only saves when the instructor presses "Save and Apply Changes" (just one example).
    - For each category/tab, perhaps there's an "overview" page that lets them see all the questions for that day. There could be some buttons could mark a question as "send to students" or "view statistics", etc. When a question is live, the instructor should be able to end the session, view incoming answers, etc.
